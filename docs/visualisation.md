# Visualisation — options compared

> For PR review and phase-5 cross-legislation visualisation. Generated by `scripts/visualize.py` into `viz/`.

## Options compared

| Option | Type | Strengths | Weaknesses | Verdict |
|--------|------|-----------|------------|---------|
| **matplotlib** (static PNG) | Static | Zero browser deps, renders in GitHub PRs natively, deterministic | No interaction, large graphs unreadable | ✅ **PR review** |
| **pyvis** (vis.js HTML) | Interactive | Physics layout, hover, zoom, self-contained HTML | Won't render in GitHub (JS), needs browser | ✅ **exploration** |
| **Graphviz** (dot) | Static/interactive | Clean hierarchical layout, good for trees | Layout engine install friction, less flexible styling | ⬜ fallback |
| **Neo4j Browser** | Interactive | Native Cypher viz, zero extra code | Needs running service, not shareable in PR | ✅ for Neo4j users |
| **D3.js custom** | Interactive | Full control | High effort, overkill for hackathon | ❌ |
| **Mermaid** (in markdown) | Static | Renders in GitHub markdown natively | Not for real graph data (manual syntax) | ✅ for docs/diagrams |

**Decision:** matplotlib PNGs for the PR (GitHub renders them inline), pyvis HTML for interactive exploration, Mermaid diagrams in docs. Neo4j Browser covers the graph-DB view when the service is up.

## Phase 5 preview (cross-legislation)

The same pipeline extends to multi-legislation visualisation:
- **Shared-concept heatmap**: jurisdictions × concepts (automated decision-making, transparency, biometrics)
- **Conflict graph**: edges where two legislations impose divergent requirements
- **Extraterritorial reach map**: which laws cite/align with which (Brussels effect)
